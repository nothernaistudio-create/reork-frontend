# REORK AI Workflow Studio

A functioning static self-service intake and diagnostic page, deliberately *not* an autonomous AI business, payment processor, real CRM or installed workflow. It runs on any static web host under `services/ai-workflows/` and requires no provider API keys.

## Real customer path

1. Visitor chooses 1–3 recurring jobs, enters current tools, desired finished outcome, manual frequency and sensitivity, and urgency.
2. Page produces an explicit fixed-outcome brief and pass/fail conditions with no automatic claims of time saved.
3. Visitor can copy it or send it by their own email client to `info@reorkai.com`. Nothing is stored automatically in the browser app, and no auto-send occurs.
4. Current REORK Gmail inbox watcher / CEO reads the genuine message and classifies an actionable prospect. A buyer reply is not a sale. Propose an initial assessment or build *only after scope, permissions, workload and deliverability review*.
5. Implementation and quote acceptance, payment and authorization require client/owner gates. Reconciliation with real destination records proves delivery before any recurring fee or testimonial.

## Known limitation

`mailto:` depends on a configured email client and doesn't provide delivery receipts. The next server milestone is a protected, privacy-respecting server-side form intake or verified business mailbox ingestion using existing REORK infrastructure. This requires spam filtering, privacy notice, explicit contact consent and durable database receipts. Do not present the demo as an autonomous sales machine.

## Why this has a legitimate commercial hypothesis

Ontario fixed-fee AI consulting competitors publicly publish engagements at $1.5k for strategy and approximately $4.5k–$15k for implementation. The idea from the owner's consulting video is a **consulting service model** rather than proof of easy $8k buyers or a guaranteed million-dollar first year. REORK should avoid making unverifiable revenue or savings promises.

## Deployment gate

Currently source staged in GitHub PR. Merging into company site's `main` will publish a reachable subpage via the existing Render static site. Owner approval for public publication, exact offer wording and contact mailbox is required. This draft collects no files, passwords, PII, customer records or payments.
